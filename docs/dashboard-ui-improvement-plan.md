# GhostTracker 운영자 대시보드 UI 개선안

작성일: 2026-09-11
대상 화면: `backend/public/operator-dashboard.html`
목표: 한 페이지에 몰린 정보를 4개 작업 메뉴로 분리하고, 운영자가 현황 확인에서 실행까지 빠르게 이동할 수 있게 한다.

## 1. 핵심 결론

현재 화면에는 운영 현황, 마케팅 성과, 고객 유형, 개별 방문 분석, 실시간 행동, 리포트가 모두 한 페이지에 있다. 각 카드는 개별적으로 이해할 수 있지만 서로 다른 목적의 정보가 같은 위계로 나열되어 다음 문제가 생긴다.

- 처음 접속했을 때 무엇을 먼저 봐야 하는지 판단하기 어렵다.
- 개별 방문을 분석하려면 긴 페이지를 오가야 한다.
- 모바일에서는 상단 조작부와 카드가 세로로 쌓여 스크롤이 길어진다.
- 실시간 자동 갱신이 방문 선택과 상세 분석 흐름을 방해할 수 있다.
- 상단 추천, 우선순위, 유입 경로처럼 비슷한 정보가 반복된다.

대시보드를 다음 4개 메뉴로 분리한다.

1. **운영 요약**: 현재 상태와 우선 조치 확인
2. **마케팅 분석**: 유입·상품·기기별 반응 비교
3. **방문 분석**: 방문 목록과 개별 행동 타임라인 분석
4. **리포트**: 일간·주간·월간·직접 선택 기간 리포트 조회와 실행 이력 관리

사이트·기간·기기·채널 필터는 네 메뉴가 공유한다. 메뉴를 이동해도 필터와 선택 상태를 유지한다.

## 2. 제안 정보 구조

```text
┌─────────────────────────────────────────────────────────────┐
│ GhostTracker | 사이트 | 기간 | 비교 기간 | 필터 | 기준 시각   │
├──────────────┬──────────────────────────────────────────────┤
│ 운영 요약     │ 선택한 메뉴의 콘텐츠                           │
│ 마케팅 분석   │                                              │
│ 방문 분석     │                                              │
│ 리포트        │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

### 데스크톱

- 왼쪽에 너비가 일정한 메뉴를 둔다.
- 상단에는 사이트·기간·필터와 데이터 기준 시각만 유지한다.
- 본문은 최대 2열로 구성한다.
- 카드나 차트를 누르면 관련 메뉴와 필터가 적용된 상세 화면으로 이동한다.

### 모바일

- 왼쪽 메뉴를 하단 탭 또는 상단 메뉴 버튼으로 전환한다.
- 상단에는 사이트와 기간만 우선 노출한다.
- 전문가 화면과 분류 갱신은 더보기 메뉴에 배치한다.
- 요약 숫자는 2열, 설명이 긴 카드와 표는 1열로 표시한다.
- 방문 분석은 `목록 → 상세 → 뒤로` 흐름을 사용한다.

## 3. 메뉴별 화면 구성

### 3.1 운영 요약

운영자가 접속 직후 현재 상태와 먼저 확인할 항목을 파악하는 화면이다.

#### 상단 핵심 지표

| 지표 | 표시 방식 |
| --- | --- |
| 방문 세션 | 현재 기간 건수, 직전 기간 대비 증감 |
| 상품 탐색 세션 | 건수와 전체 방문 대비 비율 |
| 장바구니 행동 세션 | 건수와 상품 탐색 세션 대비 비율 |
| 구매 클릭 세션 | 건수와 장바구니 행동 세션 대비 비율 |

‘방문자 수’는 고유 고객으로 오해될 수 있으므로 ‘방문 세션’으로 바꾼다. 구매 완료 데이터가 검증되기 전에는 ‘구매율’ 또는 ‘주문 성공률’보다 관측한 행동 이름을 사용한다.

#### 본문

1. 기간별 방문·상품 탐색·장바구니·구매 클릭 추이
2. 탐색 중지 신호가 많은 화면 TOP 3
3. 탭 이탈·비활성·입력 포기 등 관측된 문제 신호 TOP 3
4. 근거, 권장 조치, 대상, 확인 지표가 포함된 우선 점검 항목 TOP 3
5. 고객 유형별 세션 수, 대표 행동, 미분류 비중 요약

각 항목을 누르면 같은 사이트·기간·조건을 유지한 채 방문 분석 메뉴로 이동한다.

#### 현재 화면에서 이동할 항목

- 오늘 가장 막히는 화면 TOP 3
- 주요 문제 원인 TOP 3
- 실행 우선순위 추천 TOP 3
- 고객 유형 한눈에 보기의 요약
- 기존 상단 핵심 수치

### 3.2 마케팅 분석

유입·상품·기기에서 관심 행동과 구매 시도가 어떻게 다른지 비교하는 화면이다.

#### 채널·캠페인별 반응

| 열 | 정의 |
| --- | --- |
| 유입 경로 | channel, UTM 또는 referrer 기반 |
| 유입 세션 | 해당 경로에서 시작한 세션 |
| 상품 탐색 세션 | 상품 관련 행동이 있는 세션 |
| 장바구니 행동 세션 | 장바구니 이벤트가 있는 세션 |
| 구매 클릭 세션 | 구매 클릭 이벤트가 있는 세션 |
| 이전 기간 차이 | 건수 및 비율 변화 |

각 비율 옆에 분자와 분모를 함께 표시한다. 표본이 적은 채널에는 ‘표본 적음’을 표시한다. 광고비와 주문 매출을 연결하기 전에는 ROAS나 수익성으로 표현하지 않는다.

#### 추가 영역

- 상품별 탐색·리뷰·옵션 선택·찜·장바구니·구매 클릭
- PC·모바일별 주요 행동 발생률
- 랜딩페이지별 탐색 지속과 구매 시도
- 고객 유형별 대표 행동과 마케팅 실험 가설

상품 집계는 상품명보다 `product_id`를 우선한다. 상품 식별 누락 건수도 함께 표시한다.

#### 현재 화면에서 이동할 항목

- 유입 경로별 성과 차이
- 상단 유입 경로 TOP
- 고객 유형별 마케팅 관련 비교

### 3.3 방문 분석

방문 목록, 행동 타임라인, 유형 분석 결과를 하나의 연속된 작업 흐름으로 제공한다.

```text
┌───────────────────────┬──────────────────────────────────────┐
│ 방문 검색·필터         │ 선택한 방문                          │
│ 방문 목록              │ 시각 / 기기 / 유입 / 마지막 화면       │
│ 09:41 · mobile · 8행동 ├──────────────────────────────────────┤
│ 09:38 · desktop · 4행동│ 행동 타임라인                         │
│ ...                   │ 분석 결과와 근거 / 추천 / 리포트       │
└───────────────────────┴──────────────────────────────────────┘
```

#### 조작 흐름

1. 방문 목록에서 세션을 선택한다.
2. 상세 패널에 기본 정보와 행동 타임라인을 즉시 보여준다.
3. ‘방문 분석’ 버튼을 누르면 타임라인을 유지한 채 결과를 아래에 추가한다.
4. 유형명, 대표 행동, 분류 근거, 불확실 상태를 표시한다.
5. ‘세션 리포트’를 같은 패널에서 펼쳐 본다.

#### 목록과 실시간 피드 개선

- ‘최근 고객 1’ 대신 `시간 · 기기 · 짧은 참조번호`를 사용한다.
- 화면·기기·유입·고객 유형·중요 행동 필터를 제공한다.
- 최근 8개 고정 대신 페이지 이동 또는 더보기를 제공한다.
- 실시간 피드에는 일시정지와 ‘새 행동 N건’을 제공한다.
- 실시간 이벤트를 누르면 해당 세션을 선택한다.
- 상품·찜·장바구니·구매 클릭 등 중요 행동만 보는 필터를 제공한다.

#### 현재 화면에서 통합할 항목

- 고객 1명 자세히 보기
- 선택한 고객 분석 결과
- 방금 들어온 고객 행동
- 고객 유형의 상세 세션
- 고객 리포트

### 3.4 리포트

분석 내용을 파일로 내려받게 하기보다 대시보드 안에서 기간별 페이지로 바로 보여준다. 운영자는 기간을 바꾸면서 같은 구조의 리포트를 비교하고, 필요한 항목에서 관련 방문이나 마케팅 상세로 이동할 수 있다.

#### 리포트 선택 버튼

리포트 메뉴 상단에 다음 4개 버튼을 배치한다.

| 버튼 | 기본 기간 | 동작 |
| --- | --- | --- |
| 하루 리포트 보기 | 선택한 날짜 00:00~23:59 KST | 시간대별 변화와 당일 문제 신호 표시 |
| 주간 리포트 보기 | 선택한 주의 월요일~일요일 | 요일별 변화와 지난주 비교 표시 |
| 한달 리포트 보기 | 선택한 달의 1일~말일 | 주차별 변화와 지난달 비교 표시 |
| 기간별 리포트 보기 | 사용자가 지정한 시작일~종료일 | 같은 길이의 직전 기간과 비교 표시 |

버튼을 누르면 다른 HTML 파일이나 다운로드 창으로 이동하지 않고 리포트 메뉴의 본문을 바꾼다. 선택한 리포트 종류와 기간은 URL 쿼리 또는 hash에 남겨 새로고침과 링크 공유가 가능하게 한다. 사이트 접근 키는 URL에 넣지 않는다.

#### 공통 리포트 구성

모든 기간 리포트는 같은 정보 순서를 사용한다.

주간 리포트 화면은 기존 PDF가 제공하던 내용을 생략하지 않는다. PDF 변환 직전의 동일한 HTML 원본을 화면에도 사용해 전체 요약, 고객 유형 한눈에 보기, 전환 퍼널과 단계별 누수, 탐색 중지 집중 화면 예시, 고객 유형별 행동·페이지·AI 인사이트, 운영 개선 제안, 분석 방법과 한계, 다음 추적 지표를 모두 포함한다. PDF 내보내기는 이 화면과 같은 원본을 파일로 변환하는 보조 기능으로 유지한다.

1. **리포트 제목과 기준**
   - 사이트, 기간, 비교 기간, 생성 기준 시각
   - 진행 중인 오늘·이번 주·이번 달이면 ‘진행 중인 기간’ 표시

2. **핵심 변화 요약**
   - 방문 세션, 상품 탐색, 장바구니 행동, 구매 클릭
   - 현재 값, 직전 비교 기간 값, 차이

3. **행동 변화 차트**
   - 하루: 시간대별
   - 주간: 요일별
   - 한달: 일별 또는 주차별
   - 직접 선택: 기간 길이에 맞춰 시간·일·주 단위 자동 선택

4. **주요 관측 신호**
   - 탐색 중지 신호가 많은 화면
   - 입력 포기, 로그인 요구, 연속 클릭, 비활성 등 행동 신호
   - 건수와 관련 세션 수를 구분

5. **마케팅 변화**
   - 유입 경로·기기·상품별 주요 차이
   - 표본이 적은 항목은 별도 표시

6. **고객 유형 변화**
   - 같은 모델 버전으로 비교 가능한 경우만 증감 표시
   - 행동 근거 부족과 미분류도 함께 표시

7. **운영 액션**
   - 관측 근거, 대상 화면·유형·기기·채널
   - 권장 조치와 다음 리포트에서 확인할 지표

리포트의 카드·표·차트를 누르면 해당 조건이 적용된 운영 요약, 마케팅 분석 또는 방문 분석 메뉴로 이동한다.

#### 기간별 특화 내용

- **하루 리포트:** 시간대별 유입과 중요 행동, 실시간 이상 신호, 당일 점검 항목
- **주간 리포트:** 요일별 패턴, 지난주 대비 변화, 이번 주 실행 우선순위
- **한달 리포트:** 주차별 추세, 채널·상품·기기 구성 변화, 반복적으로 나타난 문제 신호
- **기간별 리포트:** 캠페인·프로모션·UI 변경 전후처럼 사용자가 지정한 구간 비교

#### 리포트 화면 상태

- 리포트 전환 중에는 기존 리포트를 지우지 않고 본문 위에 로딩 상태를 표시한다.
- 일부 집계 실패 시 해당 섹션만 오류와 다시 시도를 보여준다.
- 데이터가 없는 기간은 빈 리포트를 생성하지 않고 기간 변경 동작을 제공한다.
- 선택 기간이 너무 짧거나 표본이 적으면 비율 순위보다 실제 건수를 우선 표시한다.
- 리포트 생성 결과와 화면의 원본 집계가 같은 사이트·기간·필터를 사용하는지 검증한다.

파일 저장이 필요해질 경우 PDF·CSV 내보내기는 리포트 화면 오른쪽의 보조 메뉴로 둘 수 있다. 기본 행동은 항상 ‘리포트 보기’다.

실행 이력은 현재 저장 구조에 없으므로 별도 데이터 모델이 필요하다. 전후 변화만으로 조치의 인과효과를 확정하지 않는다.

#### 현재 화면에서 이동할 항목

- 운영 액션 리포트
- 일간·주간·월간·직접 선택 기간 리포트 보기
- 유형 리포트와 고객 리포트의 기간별 화면 통합
- 분류 결과 기준 시각과 분석 품질 상세

## 4. 공통 상단과 메뉴 동작

### 상단에 유지

- 현재 사이트
- 기간 및 비교 기간
- 기기·채널 필터
- 필터 초기화
- 마지막 데이터 갱신 시각
- 연결 상태

### 상단에서 이동

- 기간별 리포트 보기 버튼 → 리포트 메뉴 상단
- 전문가 화면 → 사용자 메뉴 또는 더보기
- 최신 데이터로 다시 분류 → 고객 유형 또는 리포트의 분석 상태
- 유입 경로 TOP → 마케팅 분석

### 이동 규칙

- 메뉴 이동 시 공통 필터를 유지한다.
- 운영 요약 카드에서 상세 이동 시 조건을 방문 분석에 전달한다.
- 뒤로 이동하면 스크롤 위치, 목록 필터, 선택 세션을 복원한다.
- URL에 메뉴와 공유 가능한 필터를 표현하되 사이트 키 등 민감한 값은 넣지 않는다.
- 새로고침 후 현재 메뉴는 복원하고, 오래된 개별 분석 결과는 다시 검증한다.

## 5. UI 개선 우선순위

### 우선순위 1. 사이트 변경 시 이전 분석 제거, 차트·카드 비율 기준 통일

사이트가 바뀌면 다음 상태를 즉시 초기화한다.

- 선택한 세션 ID와 이벤트
- 고객 유형 분석 결과
- 세션·유형 리포트
- 검색 입력과 활성 행
- 이전 요청의 로딩·오류 메시지

사이트 변경 전에 시작한 요청은 취소하거나 요청 식별자를 비교해 늦은 응답을 버린다.

차트와 카드의 집계 기준도 통일한다.

- 전체 세션 기준이면 미분류를 회색 항목으로 포함한다.
- 분류된 세션 기준이면 제목과 분모를 명시한다.
- 차트·카드·상세 표에 같은 유형 색상과 집계 기준을 사용한다.
- 이벤트 수와 이벤트가 발생한 세션 수를 구분한다.
- 비율 옆에 `분자 / 분모`를 제공한다.

완료 기준:

- 사이트 전환 직후 이전 사이트의 세션·분석·리포트가 보이지 않는다.
- 사이트를 연속 변경해도 마지막 사이트의 응답만 반영된다.
- 차트 합계, 카드 건수, 상세 목록 건수가 일치한다.

### 우선순위 2. 방문 목록과 상세 패널 통합, 타임라인 유지

현재 별도 카드인 방문 선택, 분석 결과, 리포트를 방문 분석 메뉴의 마스터·상세 레이아웃으로 합친다.

- 선택 즉시 타임라인 표시
- 분석 결과를 타임라인 아래에 추가
- 실행 중과 실패 시에도 타임라인 유지
- 오류는 분석 영역에만 표시
- 리포트는 같은 상세 패널에서 펼치기

완료 기준:

- 방문을 선택한 뒤 행동 근거를 잃지 않고 분석과 리포트를 확인할 수 있다.
- 새 데이터가 들어와도 현재 선택이 유지된다.
- 선택한 방문이 필터 범위에서 사라지면 이유와 돌아가기 동작을 보여준다.

### 우선순위 3. 모바일 상단 축소, 2열 중간 레이아웃 추가

| 화면 너비 | 권장 구조 |
| --- | --- |
| 1200px 이상 | 왼쪽 메뉴 + 본문 최대 2열 |
| 768~1199px | 축소 메뉴 또는 상단 탭 + 주요 카드 2열 |
| 767px 이하 | 하단 메뉴 + 핵심 지표 2열 + 콘텐츠 1열 |

모바일 상단에는 사이트·기간·연결 상태만 보여준다. 방문 상세는 전체 화면으로 열어 목록과 상세가 동시에 좁게 보이지 않도록 한다.

완료 기준:

- 320px 폭에서도 가로 스크롤 없이 주요 작업을 완료할 수 있다.
- 고정 상단이 화면 높이를 과도하게 차지하지 않는다.
- 중간 화면에서 카드가 불필요하게 한 열로 길어지지 않는다.

### 우선순위 4. 자동 갱신 중 선택·포커스 유지, 카드별 오류 처리

현재 2.5초마다 여러 API를 호출하고 화면 일부를 `innerHTML`로 다시 만든다. 다음 원칙으로 바꾼다.

- 실시간 로그·통계만 짧은 주기로 갱신한다.
- 저장된 고객 유형과 리포트는 필요할 때만 갱신한다.
- 화면 전체 대신 값과 변경된 행만 업데이트한다.
- 선택된 세션, 목록 스크롤, 입력 포커스를 유지한다.
- 사용자가 입력·선택 중이면 자동 갱신이 조작을 방해하지 않게 한다.
- 탭이 보이지 않을 때 polling을 줄이거나 중단한다.
- 중복 refresh를 막고 이전 요청을 취소한다.

오류는 카드별로 구분한다.

| 상태 | UI 처리 |
| --- | --- |
| 일부 API 실패 | 해당 카드만 오류와 다시 시도 표시 |
| 전체 연결 실패 | 공통 상태와 마지막 성공 시각 표시 |
| 데이터 없음 | 선택한 기간에 데이터가 없다는 빈 상태 |
| 분석 근거 부족 | 실패가 아닌 별도 분석 상태 |
| 이전 값 유지 | 마지막 성공 데이터의 기준 시각 표시 |

완료 기준:

- 자동 갱신 중 포커스, 목록 스크롤, 선택 세션이 유지된다.
- 한 카드의 실패가 다른 카드의 정상 데이터를 지우지 않는다.
- 같은 요청이 겹쳐 실행되지 않는다.

### 우선순위 5. 상단 중복 정보 축소, 강조색·그림자 정리

현재 큰 hero, ‘지금 운영자가 볼 것’, 유입 경로 TOP, 우선순위 추천이 비슷한 역할을 한다.

- 큰 소개 문구를 짧은 페이지 제목과 기준 기간으로 축소한다.
- ‘지금 운영자가 볼 것’과 우선 점검 항목을 통합한다.
- 유입 경로 TOP은 마케팅 분석으로 이동한다.
- 상단 지표는 방문·상품 탐색·장바구니·구매 클릭으로 정리한다.

시각 스타일은 다음 원칙을 사용한다.

- 일반 카드는 그림자를 줄이고 얇은 테두리로 구분한다.
- 한 화면에서 가장 중요한 1개 항목만 강한 배경색을 사용한다.
- 파랑은 선택·주요 동작, 초록은 정상·완료, 주황은 확인 필요, 빨강은 실제 오류에 사용한다.
- 고객 유형 색상은 차트·카드·타임라인에서 동일하게 유지한다.
- 장식용 그라데이션과 광범위한 그림자를 줄인다.
- 애니메이션을 줄이는 OS 설정을 존중한다.

완료 기준:

- 첫 화면에서 제목, 핵심 수치, 우선 점검 항목의 순서가 명확하다.
- 같은 정보를 두 카드가 반복하지 않는다.
- 색상만 보지 않아도 상태와 선택 여부를 알 수 있다.

## 6. 사용자 편의성과 접근성

### 용어 정리

- 고객 → 방문 세션: 고유 고객을 식별하지 않는 화면에서 사용
- 주문 성공 → 구매 클릭 또는 완료 화면 도달: 실제 관측 데이터에 맞춤
- 문제 원인 → 관측된 문제 신호: 인과관계 단정 방지
- 확신도 → 모델 유사도 또는 분류 점수: 실제 의미에 맞춰 표시

### 접근성

- 클릭 가능한 `div` 대신 `button`, `a` 등 의미에 맞는 요소를 사용한다.
- `outline: none`을 제거하고 `:focus-visible` 스타일을 제공한다.
- 입력창에는 화면에 보이는 label을 연결한다.
- 선택 상태를 색상과 텍스트·아이콘으로 함께 표현한다.
- 로딩·완료·오류 상태는 적절한 live region으로 알린다.
- 차트와 동일한 내용을 표 또는 접근 가능한 설명으로 제공한다.
- 텍스트와 배경의 명암 대비를 점검한다.

### 로딩과 빈 상태

| 상황 | 표시 문구와 동작 |
| --- | --- |
| 로딩 | 카드 내부 골격 화면, 다른 메뉴는 계속 사용 가능 |
| 필터 결과 없음 | 선택 조건 표시, 필터 초기화 버튼 |
| 수집 데이터 없음 | SDK 설치·연결 상태 확인 동작 |
| 분석 근거 부족 | 수집 행동은 표시하고 유형만 보류 |
| API 오류 | 원인 요약, 마지막 성공 시각, 다시 시도 |

## 8. 지표 해석 원칙

- 이벤트 횟수와 이벤트가 발생한 세션 수를 구분한다.
- 구매 클릭, 비회원 구매 버튼 행동, 주문 완료 화면 도달, 실제 주문 완료를 구분한다.
- 탭 이탈·비활성·세션 종료만으로 구매 포기 또는 UI 문제를 확정하지 않는다.
- 행동 군집은 마케팅 가설을 만드는 자료이며 고객 심리나 구매 이유를 확정하지 않는다.
- 표본이 적을 때 비율만으로 순위를 강조하지 않는다.
- 기간 비교는 같은 사이트, 시간대, 필터, 집계 정의를 사용한다.
- 고객 유형 비교는 같은 모델 버전과 분류 기준을 사용한다.
