# 쇼핑몰 SDK 삽입 — 현장 가이드

> 실제 영업 중인 가게에 설치하는 절차입니다. 매출이 걸린 사이트라 되돌릴 수 있게 진행합니다.

---

## 출발 전 (반드시)

### 1. 심을 주소 확정

팀에서 **오늘 심을 주소 하나**를 정하고, 그 주소가 살아 있는지 확인합니다.

```
https://<서버주소>/health     → {"status":"ok", ...}
https://<서버주소>/gt.js      → 자바스크립트 코드가 보임
```

둘 중 하나라도 안 되면 **설치하지 마세요.** 안 되는 주소를 심으면 사장님 사이트에서 에러만 납니다.

> 지금 서버 이전 중이라 주소가 바뀔 수 있습니다. 이전이 끝난 뒤에 가는 게 가장 안전합니다.

### 2. 접근 키 발급

사장님 쇼핑몰 주소로 키를 하나 만들어 `SITE_KEYS`에 추가합니다.

```bash
node -e "console.log(require('crypto').randomBytes(18).toString('base64url'))"
```

```
SITE_KEYS=...기존...,새키:https://사장님쇼핑몰주소
```

**설치 전에 미리 넣어두세요.** 안 그러면 현장에서 데이터 확인이 안 됩니다.

### 3. 쇼핑몰 솔루션 확인

미리 물어보고 가세요. 우리 SDK는 Cafe24에 맞춰져 있습니다.

| 솔루션 | 지원 수준 |
|---|---|
| **Cafe24** | 페이지 타입·상품 ID까지 정확히 수집 |
| 그 외 (고도몰, 아임웹, 식스샵 등) | 기본 수집은 되지만 상품·장바구니 인식이 부정확할 수 있음 |
| 자체 제작 | 확인 필요 |

Cafe24가 아니면 **"수집은 되는데 분석이 얕다"**는 점을 사장님께 미리 말씀드리세요.

### 4. 챙길 것

- 노트북 (스마트폰만으로는 확인이 어렵습니다)
- 삽입할 코드 한 줄을 메모장에 미리 복사
- 접근 키와 대시보드 주소

---

## 사장님께 먼저 설명드릴 것

설치 전에 동의를 받아야 합니다. **개인정보가 관련되기 때문입니다.**

### 무엇을 수집하나

- 어떤 페이지를 봤는지, 얼마나 머물렀는지
- 클릭·스크롤 같은 화면 조작
- 장바구니에 담았는지, 주문까지 갔는지
- 어디서 유입됐는지 (인스타그램, 검색 등)

### 무엇을 수집하지 않나

- 이름, 전화번호, 주소, 이메일
- 결제 정보, 카드번호
- 로그인 정보

입력창에 **무엇을 입력했는지는 저장하지 않고, 몇 글자를 입력했는지만** 기록합니다.

### 사장님이 확인하실 것

- **개인정보처리방침에 "행동 분석 도구 사용"을 넣어야 하는지** — 법무 판단이 필요한 부분이라, 사장님이 확인하시도록 안내드리세요. 저희가 "괜찮다"고 단정하면 안 됩니다.
- 언제든 뺄 수 있다는 점 (코드 한 줄 삭제)
- 데이터는 저희 서버에 저장되고, 사장님만 대시보드로 보실 수 있다는 점

### 솔직하게 말씀드릴 것

졸업작품 단계이고, **사이트가 느려지거나 오류가 날 가능성이 0은 아닙니다.** 그래서 되돌리는 방법을 함께 알려드린다고 설명하세요.

## 설치 절차 (Cafe24 기준)

### 1. 현재 상태 기록 — 되돌리기 위해

편집 전 화면을 **스크린샷으로 남기세요.** 뭔가 잘못됐을 때 원래대로 돌리는 유일한 근거입니다.

### 2. 편집창 열기

```
Cafe24 관리자 → 디자인 → 디자인 수정(스마트 디자인 편집창)
```

레이아웃 파일을 엽니다. 보통 `레이아웃 > 기본 레이아웃`입니다.

### 3. `</head>` 바로 위에 한 줄 추가

```html
<script async src="https://<서버주소>/gt.js"></script>
```

**`async`를 빠뜨리지 마세요.** 이게 없으면 우리 서버가 느릴 때 사장님 사이트가 그만큼 멈춥니다. 실제 손님이 보는 화면입니다.

### 4. PC·모바일 양쪽 확인

레이아웃이 나뉘어 있으면 **둘 다** 넣어야 합니다. 모바일을 빠뜨리면 절반이 안 잡힙니다.

### 5. 저장

## 설치 직후 확인 (현장에서)

### 1. 사이트가 멀쩡한지 — 이게 최우선

```
홈 → 상품 목록 → 상품 상세 → 장바구니
```

한 바퀴 돌면서 **화면이 깨지거나 느려지지 않았는지** 봅니다. 이상하면 즉시 3번(롤백)으로 갑니다.

### 2. SDK가 붙었는지

브라우저 콘솔(`F12` 또는 `⌘⌥I`)에 붙여넣기:

```js
console.log('스크립트:', [...document.scripts].map(s=>s.src).filter(s=>/gt\.js/.test(s)));
console.log('동작 여부:', typeof window.__GT === 'object');
console.log('세션:', localStorage.getItem('gt_sid'));
```

세 줄 다 값이 나와야 합니다.

**콘솔에 빨간 에러가 있는지도 확인하세요.** GhostTracker 관련 에러는 0건이어야 합니다.

### 3. 데이터가 서버까지 오는지

상품 몇 개 눌러보고 장바구니에 담은 뒤, 1분쯤 기다렸다가:

```
https://<서버주소>/api/logs/sites?key=<발급한키>
```

사장님 쇼핑몰 주소가 목록에 나오면 성공입니다.

## 문제가 생기면 — 롤백

**판단 기준은 하나입니다. 사장님 사이트에 조금이라도 이상이 있으면 즉시 뺍니다.**

원인 분석은 나중에 해도 되지만, 영업 중인 가게는 기다려주지 않습니다.

```
편집창 → 방금 추가한 <script> 한 줄 삭제 → 저장
```

이게 전부입니다. 다른 건 아무것도 안 건드렸으니 이 한 줄만 빼면 원래대로 돌아갑니다.

---

## 사장님께 남기고 올 것

### 대시보드 주소

```
https://<서버주소>/operator-dashboard.html?key=<발급한키>
```

- 첫 접속 후 주소창에서 `?key=...`가 사라지는 게 정상이라고 알려주세요
- 그 뒤로는 주소만 쳐도 들어가집니다
- **첫 접속이 30~50초 걸릴 수 있습니다** (서버가 깨어나는 시간). 고장이 아니라고 미리 말씀드리세요

### 데이터가 쌓이는 데 시간이 걸립니다

설치 당일에는 숫자가 거의 없습니다. **며칠은 지나야 의미 있는 화면이 됩니다.** 이 점을 미리 말씀드리지 않으면 "안 되는 것 같다"는 연락을 받게 됩니다.

### 연락처

문제 생겼을 때 연락할 곳과, **급하면 코드 한 줄 지우면 된다**는 것을 알려드리세요.

## 알아두실 한계

지금 상태에서 **안 되는 것**도 정확히 아셔야 사장님께 과장 없이 설명드릴 수 있습니다.

| 기능 | 상태 |
|---|---|
| 행동 수집 (클릭·스크롤·체류·유입) | 동작 |
| 장바구니·구매·옵션·수량 감지 | Cafe24면 동작 |
| 운영자 대시보드 기본 지표 | 동작 |
| **"이 고객 분석"** | **미동작** — Python 서버 미배포 |
| **"고객 유형 다시 찾기"** | **미동작** — 같은 이유 |
| **주간 PDF 리포트** | **미동작** — 사이트별 리포트 생성 필요 |
| 결제창 내부 행동 | 측정 불가 (PG사 도메인) |

"지금은 수집과 기본 지표까지 되고, AI 분석은 준비 중"이라고 말씀드리는 게 정확합니다.
